KVPro compressed state travels the whole path unchanged. Snapshot → restore of the 4-bit KV is bit-exact (measured), so moving a cache HBM ↔ DRAM ↔ NVMe adds zero extra quality loss — and it is reconstructed inside the attention kernel with no full-precision copy. A lossy transport codec cannot make this guarantee.
The advantage, per tier

HBM · capacity

~44% fewer GPUs, or ~2× the long-context users on a fixed install — the defensible, measured core.

DRAM · reuse

1.2–1.85× batch throughput and 50–86% faster first token at high cache-hit rates, losslessly.

NAND · density

~1.8× denser warm/reused cache on flash; endurance-safe because reuse is write-once-read-many.

The honest trade-off. KVPro is a capacity + quality tool, not a speed tool. On the current path decode runs ~0.13–0.67× of full precision, so latency-critical traffic stays on BF16 (credited zero above) and only memory-bound long-context traffic is routed to KVPro. An optional INT8 protected-sidecar setting refines density slightly at a measured ~3.45% decode cost — off by default, no speed claim. Quality anchor: needle-in-a-haystack matches full precision across four models / three families / two scales (measured).
