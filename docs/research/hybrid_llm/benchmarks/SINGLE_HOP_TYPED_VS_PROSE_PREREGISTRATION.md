# Single-hop typed-structure vs. flattened-prose benchmark — preregistration (DRAFT)

**DRAFT — documentation-only. Nothing here is implemented, trained, executed, or seeded. No datasets, no
models, no development or reserved runs.** This is the first controlled test of the Hybrid LLM thesis's
structured-representation hypothesis (B0 vs. B1). Always preserves, in any later work:
`ORIGINAL_BINDINGSLOTS_NEURAL_ROUTING_UNRESOLVED` · `E1_TEMPORAL_TRANSFER_PARTIAL` · `KDA_VALIDATION_BLOCKED`.

## 0. What this is / is not
**Is:** a bounded, controlled, synthetic **single-hop** relational-reasoning comparison of two
**information-equivalent** input representations on the **same** small model.
**Is not:** a BindingSlots test · a temporal-memory test · a multi-hop test · a real-model transfer test · a
production-readiness test · an efficiency benchmark · a KDA-unblocking phase. None of those may be started
from this document.

## 1. Scientific question
> Does typed entity, relation, and evidence representation **materially improve** controlled single-hop
> relational reasoning relative to an **information-equivalent** flattened-prose representation?

## 2. Primary hypothesis — `H1_SINGLE_HOP_TYPED_STRUCTURE`
A model receiving typed entity/relation/evidence records will **outperform the same model** receiving the
**same underlying facts** serialized as flattened prose on exact entity identity, single-hop relation
selection, causal relation use, evidence selection, and missing-relation abstention. The hypothesis requires
**both**:
1. **endpoint improvement** (primary-score gain over B0), **and**
2. **causal dependence** on the correct key and relation (ablation collapse where expected).
**High answer accuracy alone is insufficient** — a B1 win that does not collapse under key/relation
permutation is treated as a shortcut, not competence.

## 3. Arms (exactly two primary arms)
### B0 — information-equivalent flattened prose
The authorized working set serialized into canonical natural-language prose by a **fixed canonical
serializer**. Same underlying facts, entities, relations, evidence references, tenant context, and
missing/conflicting information as B1. **No hidden typed fields; no answer labels; no evaluator-only
metadata.**
Example: *"Invoice I991 belongs to contract C882. Contract C882 belongs to vendor V104. The supporting
evidence record is E17."*

### B1 — typed structured representation
The **same** working set as explicit typed objects. Permitted fields: entity type · canonical entity
identity · typed attributes · relation type · source entity · target entity · evidence reference · tenant
scope · schema version (where applicable). **B1 must not receive any information absent from B0.**
Example:
```
entity:   { type: invoice, id: I991 }
relation: { type: belongs_to_contract, source: invoice:I991, target: contract:C882, evidence_ref: E17 }
```

The **only** experimental difference between arms is the **input representation**.

## 4. Frozen model comparison (the later experiment)
Same **architecture · initialization policy · parameter count · training steps · optimizer · learning rate
· batch order · questions · underlying records · output schema · evaluation logic** across B0 and B1.
**Excluded** (must not appear in either arm): BindingSlots · E1 memory · recurrent architecture changes ·
bounded quadratic reader · external-table correction at answer time · real pretrained-model adaptation · any
capacity difference between arms.

## 5. Controlled task family
A bounded **synthetic single-hop** relational benchmark. Each example = a small authorized working set with
entities, one or more candidate relations, evidence references, tenant labels, and plausible distractors.
Multiple enterprise-style **domains** (procurement · hiring · cybersecurity · customer support · compliance
· agent governance). **Reasoning depth is single-hop; no multi-hop paths in this phase.**

## 6. Task splits (evaluated separately)
- **S1 — exact entity identity:** select the correct entity among duplicate/similar names.
- **S2 — foreign-key target:** identify the exact target of one explicit relation (e.g., invoice → contract).
- **S3 — valid vs. invalid relation:** decide whether a proposed relation is supported by the working set.
- **S4 — duplicate-name / content-similar decoys:** distinguish entities with similar names/attributes.
- **S5 — evidence-reference selection:** return the evidence reference supporting the selected entity/relation.
- **S6 — missing relation / abstention:** abstain when the required relation is absent.
- **S7 — cross-tenant decoys:** reject plausible entities/relations belonging to another tenant.
- **S8 — stable direct cases:** straightforward cases confirming the task itself is not needlessly hard.

## 7. Deterministic authority (ground-truth contract)
Ground truth is generated by a **deterministic relational / SQL-equivalent evaluator**. For every example,
store: authoritative entity identity · authoritative relation target · relation validity · authoritative
evidence reference · tenant scope · expected abstention state. **The model never defines its own ground
truth**; targets are used only to score predictions after the fact.

## 8. Information-equivalence requirements
A **mechanical information-equivalence verifier** must confirm, for every B0/B1 pair: identical entities ·
identical attributes · identical relation facts · identical evidence references · identical tenant scope ·
identical missing facts · identical conflicts · **no extra schema hint in B1 absent from B0** (unless it is
the tested structural representation itself, declared as such) · **no answer token/label** embedded in
either representation. Compute a **canonical fact-set hash** shared by B0 and B1; **fail closed** if a pair
does not map to the same underlying fact set.

## 9. Input-budget fairness
Preregister input-length control and report per pair: **B0 token count · B1 token count · record count ·
entity count · relation count**. Use one disciplined approach: (1) **matched maximum token budget**, or
(2) **report both raw and token-matched** results. **B1 must not silently get a larger usable context.** If
token matching requires truncation, the truncation policy is **identical in information priority** across
arms and **frozen before execution**.

## 10. Causal ablations (all required; evaluated separately from endpoint accuracy)
- **A1 — primary-key permutation:** permute entity identities preserving superficial content → performance
  should **materially degrade**.
- **A2 — relation-target permutation:** replace the correct target with a plausible wrong one → **degrade**.
- **A3 — relation removal:** remove the required relation → model should **abstain / report insufficient
  evidence**.
- **A4 — evidence permutation:** swap evidence references across similar relations → evidence selection
  **degrades**.
- **A5 — cross-tenant substitution:** replace a valid in-tenant target with a similar out-of-tenant target →
  **unauthorized selection must remain zero**.
- **A6 — lexical decoy control:** add high-lexical-similarity but relationally-incorrect names/descriptions.

## 11. Shortcut & leakage protections
See `SINGLE_HOP_TYPED_VS_PROSE_SHORTCUT_ANALYSIS.md` for the full analysis. Summary — the preregistration
prohibits: answer labels in field names · relation types that directly encode the answer · evaluator-only
IDs · fixed output-position shortcuts · unique token prefixes revealing arm/answer · train/final entity
overlap · trivializing train/final template overlap · B1-only access to authoritative answers · B0
serializer artifacts correlated with the label · external-table lookup during inference · post-hoc threshold
selection · final-cohort-driven prompt/serializer changes. Required near-chance baselines: lexical overlap ·
latest/first-record heuristic · entity-frequency · relation-type frequency · evidence-position heuristic.

## 12. Metrics (per arm, seed, domain, split, and ablation)
exact entity accuracy · foreign-key target accuracy · relation-validity accuracy · evidence-reference
precision · evidence-reference recall · missing-relation abstention accuracy · cross-tenant unauthorized
inclusion · end-to-end answer accuracy · calibration/confidence (where applicable) · causal-ablation
collapse · token count · runtime · parameter count · deterministic replay · leakage/shortcut results.
**Endpoint accuracy is kept separate from causal purity and evidence integrity.**

## 13. Primary outcome
Primary score = a **preregistered macro-average** of **S1 · S2 · S3 · S5 · S6**. **Each primary split must
also clear its own minimum floor** — a strong average may **not** hide failure on abstention (S6), evidence
(S5), or tenant isolation (checked via S7/A5). (S4/S7/S8 and all ablations reported alongside.)

## 14. Gate structure (structure frozen now; numbers `APPROVAL_REQUIRED_BEFORE_EXECUTION`)
Required gates:
- **B1 materially outperforms B0** on the primary score, by a **meaningful frozen minimum effect size**;
- **≥ 4 of 5** fresh final seeds pass;
- **every primary split clears its own floor**;
- **causal ablations collapse** where expected (A1/A2/A4 degrade; A3 → abstention);
- **relation removal (A3) produces abstention**;
- **unauthorized cross-tenant inclusion is zero** (S7/A5);
- **evidence-reference integrity** passes (S5 precision/recall floors);
- **stable direct cases (S8) do not materially regress**;
- **deterministic replay** passes; **information-equivalence** verification passes; **leakage/shortcut**
  suite passes; **compute budget** not exceeded.
Gates are grounded in **non-reserved fixtures and meaningful competence bars**; **not** set equal to
observed development performance. All numeric values `APPROVAL_REQUIRED_BEFORE_EXECUTION`.

## 18. Advancement rule (strategic go/no-go)
- **If validated:** only then may a **separately authorized** Stage-2 preregistration be drafted (multi-hop
  join paths · false-but-plausible paths · composite keys · schema versions · broader tenant decoys). **No

  grounding · abstention · tenant isolation · information-equivalence. **No automatic advance.**
- **If not found:** **stop** the structured-neural relational-representation line; retain deterministic
  retrieval · conventional bounded reasoning · evidence-grounded outputs · governance separation.
