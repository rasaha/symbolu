# B1 — Stage-1 Parser → Varṇa-Mapping Integration Audit (docs/data-only)

**Readiness verdict: `BLOCKED_BY_MISSING_VOWEL_AND_MARKER_MAPPINGS`.** This is a **structural faithfulness** audit
of how the corrected native-Sanskrit parser (`sanskrit_stage1_parser.py`, commit `a1988394`) resolves against the
current varṇa mapping table (`frozen/varna_polarity_table_v3.json`). It is **not** semantic validation: it judges
no meanings, authors none, selects no polarity, runs no judge. Generated by
`b1_stage1_mapping_integration_audit.py`; machine-readable outputs in `stage1_mapping_integration/`.

**Structure, not validated meaning.** No `GENUTILITY_*`; no `ONTOLOGICAL_SIGNAL`. Parser, table, Track-G, and the
provenance register are unchanged; no vowel meanings added, no opposites authored, no repair.

---

## Headline

- **The identity bridge is clean.** All **33** recognized consonant graphemes resolve **1:1** to distinct table
  keys — the map is injective, so **no distinct Sanskrit varṇa is collapsed, merged, aliased, or mis-mapped**.
  Order and multiplicity are preserved in **every** audited word; nothing is silently dropped or deduplicated.
- **But the full parsed inventory is not mappable.** All **14 vowels**, **anusvāra**, **visarga**, and
  **candrabindu** have **no table entry**. Frequency-weighted over the 110-word seed corpus, **45% of all
  phonological tokens are `MISSING_TABLE_ENTRY`** and only **49% resolve to an active entry**. **No word
  containing a vowel is `FULLY_MAPPABLE`.**
- **The table's active/inactive flag is stale w.r.t. the native parser.** `practically_reachable` describes the old
  English-G2P bridge; the native parser emits **every** consonant grapheme, so **14 "inactive" keys are in fact
  reachable** (`bha cha dda ddha dha gha jha kha nna nya pha ssa tta ttha`).

## A. Canonical identity bridge (`identity_bridge.json` / `.csv`)

Parser bare-consonant IAST → table key, verified injective:

| parser IAST → key | … | … |
|---|---|---|
| k→ka, kh→kha, g→ga, gh→gha, ṅ→**nga** | c→ca, ch→cha, j→ja, jh→jha, ñ→**nya** | ṭ→**tta**, ṭh→**ttha**, ḍ→**dda**, ḍh→**ddha**, ṇ→**nna** |
| t→ta, th→tha, d→da, dh→dha, n→na | p→pa, ph→pha, b→ba, bh→bha, m→ma | y→ya, r→ra, l→la, v→va |
| ś→**sha**, ṣ→**ssa**, s→sa, h→ha | **ḷ (ळ) → (no key)** | conjunct **kṣa** never emitted (parser gives k+ṣ) |

- **`ḷ` (retroflex lateral ळ)** → `MISSING_TABLE_ENTRY` (no key in the 34-key table).
- **`ksha` (kṣa)** is a table key with **no parser producer**: the parser decomposes क्ष → क + ष (`k` + `ṣ` =
  `ka` + `ssa`). So the table's `ksha` entry is structurally unreachable from the native parser.
- Vowels, anusvāra, visarga, candrabindu, markers, and unsupported bases are all included in the bridge with the
  appropriate non-resolving status (see below). No meaning is invented for any of them.

## B. Word-by-word resolution (`word_resolution.json`)

Format (real keys), e.g. `koṭi` (कोटि):

```
word: कोटि    status: CONTRADICTORY_MAPPING   order_preserved: true  multiplicity_preserved: true
  क  k  -> ka   EXACT_ACTIVE
  ो  o  -> null MISSING_TABLE_ENTRY
  ट  ṭ  -> tta  CONTRADICTORY_ENTRY      (table marks tta unreachable; native parser emits it)
  ि  i  -> null MISSING_TABLE_ENTRY
```

`saṃskāra` (संस्कार) shows anusvāra unresolved and both `s` kept: `s→sa, a→∅, ṃ→∅(MISSING), s→sa, k→ka, ā→∅,
r→ra, a→∅`. `sattva` keeps the geminate `t,t` (multiplicity). `kṣatra` decomposes `k+ṣ` in order. In **every**
audited word (30 probes + 110 seed) `order_preserved` and `multiplicity_preserved` are **true**.

## D. Mapping-correctness checks (all pass structurally)

| distinction | probe | result |
|---|---|---|
| dental vs retroflex stop | `gati` t→ta / `koṭi` ṭ→**tta** | distinct ✔ |
| palatal/retroflex/dental sibilant | `śiva` ś→sha / `viṣṇu` ṣ→ssa / `rasa` s→sa | distinct ✔ |
| aspirated vs unaspirated | `khaga` kh→kha vs g→ga / `śraddhā` d→da vs dh→dha | distinct ✔ |
| nasals | ṅ→nga, ñ→nya, ṇ→nna, n→na, m→ma | all distinct ✔ |
| ṛ vowel vs consonantal r | `ṛtu` ṛ→∅(vowel, MISSING) vs `rāma` r→ra | distinct ✔ |
| anusvāra vs homorganic nasal | `saṃskāra` ṃ→∅ (kept as ṃ, **not** resolved) | preserved ✔ |
| visarga vs h | `duḥkha` ḥ→∅(MISSING) vs `haṃsa` h→ha | distinct ✔ |
| conjunct order | `kṣatra` → k, ṣ, a, t, r, a | order kept ✔ |
| gemination / multiplicity | `sattva` → …t, t… ; `anna` → n, n | both kept ✔ |
| inherent अ | `bala` → b, a, l, a | emitted (all MISSING) ✔ |
| independent vs dependent vowel | `agni` अ / `kāla` ा → same identity | unified ✔ |
| ḷ vocalic vs retroflex lateral ळ | rendered `l̥` vs `ḷ` (neither has a key) | distinct ids ✔ |

**No alias collapses two distinct Sanskrit varṇas.** The only many-to-one risk (dental vs retroflex, palatal vs
retroflex sibilant) is correctly kept apart by the table's `ta/tta`, `da/dda`, `sha/ssa`, `na/nna` key scheme.

## E. Full-word integrity

For all 140 audited words: atomic-count == resolution-count, order equal, multiplicity equal, no silent omission,
no deduplication, no routing through English orthography/G2P (the parser imports none), no semantic scoring. A word
with any missing unit is marked **`PARTIALLY_MAPPABLE`** (or `CONTRADICTORY_MAPPING` if it contains ṭa), never
"fully mapped after dropping the missing units." **Probe/seed word-status: 0 `FULLY_MAPPABLE`.**

## F. Existing Sanskrit seed list vs native parser (`trackg_decomposition_diff.json`)

The frozen seed list (`frozen/word_list.json`, 110 words) stores **IAST-derived, consonant-only** decompositions.
Compared against the native parser (all 110 round-tripped through the audit's validated IAST→Devanāgarī helper):

- **110 / 110** old decompositions **dropped every vowel** (`OLD_DROPPED_VOWELS`).
- The **consonant skeleton matches** in the vast majority (e.g. `kāla` old `[ka,la]` = new consonants `[ka,la]`),
  confirming the old table captured only the consonantal projection.
- Words with anusvāra/visarga additionally show `OLD_OMITTED_ANUSVARA_OR_VISARGA`.
- Example `agni`: old `[ga,na]` (consonants only, leading vowel dropped) vs native `[a, g, n, i]` — the native
  parser recovers the independent onset vowel and both matra vowels the old pipeline discarded.

*(This is a structural comparison only. Track-G artifacts and its prior verdict are unchanged and not reinterpreted.)*

## G. Discrepancies (`discrepancies.json`)

1. **Missing categories:** all 14 vowels (`a ā i ī u ū ṛ ṝ l̥ l̥̄ e ai o au`), anusvāra ṃ, visarga ḥ, candrabindu, and
   the retroflex lateral `ḷ` (ळ) — no table entries.
2. **`ksha` table key has no parser producer** (kṣa is decomposed).
3. **14 keys are native-reachable but table-`inactive`** — the `practically_reachable` flag is stale for the native
   parser. Only `tta` carries the register's explicit `REACHABILITY_CONTRADICTION`; `dda` is in the same situation
   but was not flagged in the register (surfaced here, not silently reconciled).
4. **Pole-provenance flags on keys** (from the register, identity-independent): `sha`/`ssa` `SIBILANT_SWAP`,
   `ha` `BACK_FIT`, `pa` `META_STALE_PA`, `ttha` `META_STALE_TTHA`, `tha` `DOC_VS_CODE_TH`. These concern pole
   **content/metadata**, not the identity resolution, which is exact.
5. **IAST→Devanāgarī helper:** 110/110 seed words round-tripped (parser IAST echo == input IAST), so the audit
   inputs are faithful.

**No identity-bridge errors** (no wrong mapping, no collapse, no silent drop) were found — the block is coverage,
not correctness.

## Readiness verdict

**`BLOCKED_BY_MISSING_VOWEL_AND_MARKER_MAPPINGS`.** The structural connection is faithful, but the current table is
a consonant-only artifact: vowels, anusvāra, visarga, candrabindu (and the retroflex lateral) have no entries, and
they dominate real Sanskrit token frequency. The bridge is ready for a **consonant-only** review, but a complete
integration requires the missing inventory. (Secondary: the stale active/inactive metadata and the tta/dda
reachability contradiction.)

**Single recommended next step:** run a **provenance-first inventory decision for the missing vowel / anusvāra /
visarga / candrabindu categories** (author-or-attest under the same blinding/pre-registration discipline as the
consonants), and re-sync the table's `practically_reachable` flag to native-parser reachability — **before** any
consonant-only mapping review is treated as complete and before any composition/semantic step.
