# Phase 5C — int4_protected KV-cache usage

v1 ship-config recipe for running Qwen2.5-7B-Instruct with a
4× larger effective KV cache on the same GPU.

## TL;DR

```python
import kv_policy.int4_protected           # registers the backend
from vllm import LLM, SamplingParams

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    kv_cache_dtype="int4_protected",
    block_size=32,                          # required
    max_model_len=4096,
)
out = llm.generate(["Hello"], SamplingParams(temperature=0.0, max_tokens=64))
print(out[0].outputs[0].text)
```

That's the entire setup. Two lines beyond stock vLLM:
1. `import kv_policy.int4_protected` (registers the backend).
2. Two extra LLM kwargs (`kv_cache_dtype="int4_protected"`, `block_size=32`).

## One-line factory (alternative)

```python
from kv_policy.int4_protected import Int4ProtectedLLM
from vllm import SamplingParams

llm = Int4ProtectedLLM(model="Qwen/Qwen2.5-7B-Instruct", max_model_len=4096)
out = llm.generate(["Hello"], SamplingParams(temperature=0.0, max_tokens=64))
```

The factory enforces the `block_size=32` constraint and sets v1-
recommended defaults (`enforce_eager=True`, `gpu_memory_utilization=0.5`).

## Prerequisites

1. **vLLM dev build with kernel patches applied** through Phase 2.6.2.
   The vendored vllm-flash-attn must have:
     - Phase 2.4.1a/b — packed-K plumbing + kernel reader
     - Phase 2.6.0/1/2 — packed-V helpers + kernel reader
     - Phase 2.5 — `Is_int4kv` template gating
     - Phase 3/4 — V transform + protect-mask blend

2. **Calibrated per-model protect mask** at `$PROTECT_MASK_PATH`
   (default `/workspace/dev/build-logs/qwen2_5_7b_protect_mask_4pct.pt`).
   Generated by `calibrate_phase5b_protect_mask.py`. The artifact is a
   dict containing `{"mask": (num_layers, H_kv, D) int8, ...}`.

3. **`kv_policy` package** on `PYTHONPATH` (typically
   `/workspace/symbolu/CTM_plus/KVPolicy`).

## Constraints

| Constraint | Reason | Override path |
|---|---|---|
| `block_size = 32` | Kernel `kInt4GroupSize` is a compile-time `constexpr`. | Rebuild kernel with different group size (~1-2 hrs CUDA work). |
| `batch = 1` | PagedKVWriter holds per-layer staging + seq_pos for one sequence at a time. | Phase 5B.6 (multi-batch — per-`(layer, seq)` state). |
| Qwen2.5-7B (sm80) | Protect mask + kernel instantiation calibrated for this model. | Recalibrate mask + add new kernel instantiation for other models. |
| `max_model_len <= 4096` | Default bf16 backing buffer at 4096 max_seqlen. | Set `$PHASE5B_4C_BF16_BACKING_MAX_SEQLEN=8192` (etc.). Each doubling = +224 MB. |

## What you get

- **2.01× cuda blocks** at the same `gpu_memory_utilization` budget
  (uint8 D=128 paged cache vs stock bf16 D=128).
- **100% needle retrieval** matching stock vLLM on Phase 5B.5 acceptance
  tests (15/15 across 3 context-length buckets).
- **Bit-identical greedy decode** on some prompts (3/5 in Phase 5B.4c.3
  char-diff); mean 67% common-prefix overlap with stock across diverse
  content.

## Memory accounting (Qwen2.5-7B, max_model_len=4096, gpu_mem_util=0.5)

| Component | Bytes |
|---|---|
| vLLM paged uint8 cache | 24 GB (= stock bf16 reserve; holds 2× tokens) |
| External sidecars (K_scale + K_xmin + K_protect + V_scale + V_xmin) | ~4.2 GB |
| BF16 K/V backing (small-S kernel workaround) | ~224 MB |
| **Total KV-related GPU** | **~28.4 GB** for ~898K concurrent slots |
| Stock baseline | 24 GB for ~223K concurrent slots |

**Net: 4× concurrent-slot capacity at +18% GPU memory.**

## Migration from the two-step install pattern

Old pattern (pre-5C, still works):

```python
from kv_policy.phase5b_backend_install import (
    enable_int4_protected_backend, install_int4_protected_backend,
)
enable_int4_protected_backend()
llm = LLM(model=..., kv_cache_dtype="int4_protected", block_size=32)
install_int4_protected_backend(
    llm.llm_engine.model_executor.driver_worker.model_runner.model,
)
```

New pattern (5C):

```python
import kv_policy.int4_protected      # one line replaces enable+install
llm = LLM(model=..., kv_cache_dtype="int4_protected", block_size=32)
```

The post-construction `install_int4_protected_backend` call is no
longer required — layer indices auto-resolve from `layer.layer_name`
on first forward. The legacy two-step still works if you need
explicit layer-idx pre-assignment.

## Knobs (env vars)

| Variable | Default | Purpose |
|---|---|---|
| `PROTECT_MASK_PATH` | `/workspace/dev/build-logs/qwen2_5_7b_protect_mask_4pct.pt` | Path to calibrated per-model protect-mask artifact. |
| `PHASE5B_4C_BF16_BACKING_MAX_SEQLEN` | `4096` | Size of per-layer BF16 K/V backing buffer. Increase for longer contexts. |
| `PHASE5B_4C_BF16_V` | unset | Debug switch — stash V as bf16 instead of packing. Used during 5B.4c.3 V-isolation. Production runs leave unset. |

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `TypeError: Protect mask artifact ... is dict, expected Tensor` | Old loader; pull latest kv_policy. | `git pull origin claude/dazzling-dijkstra-EJXOV` |
| `RuntimeError: PagedKVWriter requires block_size=32` | block_size != 32. | Pass `block_size=32` to LLM. |
| `Cannot determine _phase5b_layer_idx` | Attention has no `.layer_name` attribute and you skipped `install_int4_protected_backend`. | Either upgrade vLLM (0.7.3 sets `layer_name`) or call the legacy install. |
| Generation produces gibberish | Likely missing the bf16 backing fix (pre-`1211993`). | Pull latest; verify `_phase5b_backend_marker == "5B.4c.3"`. |
| `NotImplementedError: Int4Protected batch=1 v1; got batch=N` | Tried multi-prompt batched generation. | Serialize generations: one `llm.generate([prompt])` per call. |
