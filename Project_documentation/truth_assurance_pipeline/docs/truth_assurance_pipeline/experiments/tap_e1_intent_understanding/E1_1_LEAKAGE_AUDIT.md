## Discipline narrative (full disclosure)

1. Config selection used the **dev split only** (20 cases with cached model output).
2. Gates were **preregistered** (`preregistration_v11.json`) before hidden scoring.
3. During harness development the hidden aggregate was observed and surfaced a **metric
   bug** (`invented_action` paraphrase false positives). That bug is **also present on
   the dev split** (4 dev cases), so the correction is justified by dev diagnostics, not
   by hidden results. It was applied **uniformly** to every baseline and to the
   deterministic interpreter, and TAP-E1's `metrics.py` was **not** modified (the
   correction lives in `metrics_e11.py`).
4. **No interpreter implementation and no corpus prompt/label was changed in response to
   hidden results.** Only the (uniform) metric scoring was corrected, per the
   metric-audit mandate.
5. A fully independent confirmation would require a **fresh hidden set** and an
   **independent interpreter/author** (recommended next step) — the current run cannot
   fully rule out that observing the hidden aggregate influenced the metric fix, even
   though the fix is dev-justified.

## Structural leakage guarantees

- Hidden **gold labels cannot be imported** through `loader.public_cases` (a key
  whitelist assertion raises otherwise).
- The interpreter only ever receives a `RawUserRequest` built from the public
  projection.
- The same model both authored and interpreted the corpus — this is **not** a label
  leak (gold was never shown at inference) but **is** an author==interpreter confound,
  disclosed throughout.
