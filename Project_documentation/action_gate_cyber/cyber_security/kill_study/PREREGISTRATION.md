# BCVF-Bio Adversarial Synthetic Kill Study — Preregistration & Analysis Plan

**Written before any results were interpreted.** This document fixes the hypothesis,
detector arms, trajectory families, metrics, statistics, and decision rule in advance.
The decision rule is mechanical: the verdict is computed from held-out numbers by
`analysis.py`, not chosen after inspecting them.

Scope: **synthetic falsification only.** No human data, no biometric-validity claim, no
production-security claim, no patent conclusion, no FSCS. Every trajectory is generated by a
deterministic simulator; "attacker" and "user" are synthetic vector processes.

---

## 1. Primary question

> Does the BCVF second-order detector add measurable value beyond a tuned local-linear-trend
> (LLT) Kalman filter + CUSUM when all non-detector protections are equalized?

The comparison of record is **arm H (full guarded BCVF composite)** vs **arm I (full guarded
LLT-Kalman + CUSUM)**. Both wear the *identical* guard layer; the detector core is the only
changing factor.

## 2. Hypotheses

- **H0 (null, the thing we try to confirm):** with guards equalized, BCVF's second-order core
  does not improve the held-out DET frontier, damage-weighted detection, or attacker-direction
  template displacement over LLT+CUSUM on adaptive attacks.
- **H1 (alternative):** BCVF's second-order core produces a statistically supported improvement
  on at least one of those three axes against slow, poisoning, or detector-aware attacks, after
  equalization.

The study is designed so that H1 must survive an adversary-first evaluation to be accepted.
We do **not** get to keep a clean abrupt-attack result if the adaptive result fails.

## 3. Detector arms

| Arm | Core | Guarded? |
|-----|------|----------|
| A | Static threshold on identity mismatch `‖m_fast − μ_u‖` | no |
| B | EWMA fast/slow disagreement `‖d‖`, `d = m_fast − m_slow` | no |
| C | CUSUM on raw disagreement `‖d‖` | no |
| D | CUSUM on anchor-distance / identity mismatch `‖m_fast − μ_u‖` | no |
| E | LLT-Kalman (level+slope) + CUSUM on innovations (pure) | no |
| F | BCVF second-order term only: gated pseudo-Huber of `‖Δ²d‖` | no |
| G | BCVF composite: `z(identity) + z(disagreement) + z(‖Δ²d‖)` | no |
| H | **Full guarded BCVF composite** — `z(identity)+z(disagreement)+z(second-order)` | yes |
| I | **Full guarded LLT+CUSUM composite** — `z(identity)+z(disagreement)+z(LLT-CUSUM)` | yes |

**Fair-baseline rationale (anti-rigging).** Arms H and I are structurally
identical composites — verified-identity channel + fast/slow disagreement
channel + a temporal-change channel — and differ **only** in that channel: H
uses the BCVF second-order term, I uses the LLT-Kalman+CUSUM innovation. Each
channel is z-scored against the shared DEV-legit null so none is implicitly
up-weighted. This does two things: (1) it makes H vs I a clean attribution test
of the second-order term specifically; (2) it gives the LLT+CUSUM baseline the
*same* identity/disagreement information BCVF has. An identity-blind pure-LLT
baseline (arm E, kept as a reference) would let BCVF's identity channel win the
comparison for reasons unrelated to the second-order term — i.e. it would rig
the test toward BCVF. The strong baseline is therefore given every channel
BCVF has. This strengthens, never weakens, LLT+CUSUM.

## 4. Equalization requirement

Guarded arms H and I share, byte-for-byte, the same guard layer and the same guarded observer
states. Specifically identical:

- verified-anchor bound on the slow template (`‖m_slow − μ_u‖ ≤ anchor_radius`),
- template-update gate (`update slow only when ‖d‖ < gate_threshold`),
- cumulative displacement limit on the slow template,
- deadband (k·σ EMA-centered significance gate on the core score),
- hysteresis (`θ_on > θ_off`),
- persistence rule (alarm requires `m`-of-`K` windows),
- graduated response policy (continue / observe / challenge / restrict).

The slow observer (`m_fast`, `m_slow`, `d`) is computed **once** under the shared guarded update
and read by both cores. Only the scalar core-score function differs between H and I. Non-guarded
arms A–G use unrestricted adaptation (gate always on) and immediate thresholding, to isolate the
detector core with no protection.

## 5. Trajectory families

Legitimate (challenges here are false challenges):
1. Stable legitimate behavior
2. Constant-offset legitimate behavior
3. Linear legitimate drift
4. Smooth nonlinear legitimate drift (bounded, low curvature)
5. Abrupt legitimate device/context switch

Attacks (missing a challenge here is a missed detection):
6. Abrupt attacker takeover
7. Slow linear attacker takeover
8. Smooth low-curvature attacker takeover
9. Gate-aware gradual poisoning (attacker stays under the update gate)
10. Detector-aware optimized trajectory (ramp shape chosen to minimize peak `‖Δ²d‖` while
    reaching the attacker target — the worst case *for BCVF*)
11. Replay-like low-noise spoof (matches `μ_u`; no liveness channel exists — expected to defeat
    **all** arms, included to show the shared blind spot honestly)
12. Sparse / missing-evidence attack (abrupt or slow takeover with dropped observations)

Adaptive-attack families (the security test) are **7, 8, 9, 10**. Family 11 is a control that
should fail for everyone; family 12 feeds the sparse-evidence failure-rate metric.

## 6. Sweep axes

observation noise σ; attacker/user separation; ramp curvature; ramp duration; observer update
rates (α_fast, α_slow); anchor radius; gate threshold; missing-data rate. Dev and held-out
occupy **disjoint** ranges of σ, separation, and duration (see `config.py`
`DEV_GRID` / `EVAL_GRID`). Thresholds are tuned only on dev; all reported numbers are held-out.

## 7. Metrics (all reported on held-out seeds)

- **DET frontier:** false-challenge rate vs detection rate over a full threshold sweep (no single
  operating point cherry-picked). Summarized by area between the frontier and the FAR axis
  restricted to a preregistered FAR budget, and by detection at fixed FAR.
- **Detection delay:** median and p95 (steps from takeover onset to first challenge), at the
  dev-tuned operating point.
- **Damage-weighted detection loss:** `𝒟 = Σ_{τ=onset}^{response} w_action(τ)` with a
  **fixed, preregistered attacker action policy** (front-loaded worst case:
  weights ramp critical→low), reported as mean over attack events (min-max over the fixed
  policy; the policy is not tuned per arm).
- **Attacker-direction displacement `D_∥ = ⟨m_slow(T) − m_slow(0), v_attack⟩`** and orthogonal
  `D_⊥`, over poisoning family 9.
- **Acceptance-margin erosion** `M_erosion = score(μ_a, m_slow(T)) − score(μ_a, m_slow(0))`,
  score = negative distance, over poisoning family 9.
- **Template-update amount** `Σ ‖Δ m_slow‖`.
- **Challenge rate** on legitimate families.
- **Failure rate under sparse evidence** (family 12): fraction of attack events undetected.
- **Calibration sensitivity:** spread of false-challenge rate across σ at a fixed threshold.

## 8. Statistics

- Many independently seeded events; each seed produces the *same* trajectory for every arm
  (paired design).
- Paired per-seed differences (H − I) for each key metric.
- **Bootstrap 95% CIs** over seeds (resample seeds with replacement, `N_BOOT` resamples,
  2.5/97.5 percentiles), clustered by seed.
- No selective threshold reporting: DET curves reported in full; operating-point metrics use the
  single dev-tuned threshold.
- Thresholds tuned on dev seeds **and** dev parameter ranges; evaluated on held-out seeds **and**
  held-out parameter ranges.

## 9. Preregistered decision rule (mechanical)

Let the adaptive-attack set = families {7, 8, 9, 10}. Compare H vs I on held-out, paired,
with bootstrap CIs. "Improvement" = the 95% bootstrap CI of the paired difference lies strictly
on the favorable side of zero.

1. **SECOND_ORDER_ADDS_SECURITY_VALUE** — iff H shows a statistically supported improvement over
   I on **at least one** of {DET detection-at-fixed-FAR, damage-weighted loss, `D_∥`} on the
   **adaptive-attack set**.
2. Else **FRICTION_ONLY_INCREMENTAL_VALUE** — iff H shows a statistically supported reduction in
   false challenges on legitimate-drift families {2,3,4} at matched detection, but no adaptive
   security improvement per (1).
3. Else **SECOND_ORDER_DIFFERENTIATION_NOT_SUPPORTED**.

The verdict is emitted by `analysis.py` from the held-out numbers. It is not editable after the
fact. If results contradict a prior expectation, the results stand.

## 10. Anti-rescue commitments

- The hypothesis, arms, families, metrics, and decision rule above are frozen before running.
- LLT-Kalman + CUSUM (arms E, I) will not be omitted or weakened.
- No claim of novelty, biometric validity, or production security will be drawn from synthetic
  results, regardless of verdict.
- The detector-aware family (10) is generated to evade the *second-order* signal specifically —
  i.e. the study actively constructs the case most likely to falsify H1, not to confirm it.
