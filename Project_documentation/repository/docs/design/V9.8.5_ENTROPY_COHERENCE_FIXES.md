## Fix 1: PID Coherence Input (CRITICAL)

### The Problem

The PID controller's coherence gate was non-functional because it always received a hardcoded value of 0.75.

**Code Path (Before):**
```
evaluate()
  → returns {"ppl": X}  // Discards coherence!
  → val_metrics.get('coherence', 0.75)  // Always gets default
  → authority_controller.update(val_ppl, 0.75)  // PID is blind
```

### Root Cause Analysis

The `evaluate()` function at `train_unified_llm.py:13396` was:

```python
# BEFORE: Discards all metrics except PPL
return avg_loss, {"ppl": math.exp(min(avg_loss, 20))}
```

Even though coherence was computed during the evaluation loop (line 13379 for gen2 models), the final return statement threw away all metrics.

Meanwhile, the training loop computed `toroidal_coherence` (O1↔O12 cosine similarity) every step, but this value was never passed to the PID.

### The Fix

**Location:** `train_unified_llm.py:12821-12829`

```python
# V9.8.5: Use REAL toroidal coherence for PID, not hardcoded default
# The evaluate() function discards coherence metrics, so we use the
# training loop's toroidal_coherence which measures actual cognitive
# continuity (O1↔O12 cosine similarity).
if 'toroidal_coherence' in dir() and toroidal_coherence is not None:
    current_coh = toroidal_coherence
else:
    current_coh = val_metrics.get('coherence', 0.75)
```

### Reasoning

1. **Toroidal coherence is the right metric:**
   - Measures cognitive continuity between steps
   - O1 (input layer) ↔ O12 (synthesis layer) similarity
   - High coherence = stable trajectory = healthy learning
   - Low coherence = cognitive discontinuity = model struggling

2. **Timing is acceptable:**
   - PID updates happen at eval intervals
   - Using training-time coherence (from last step before eval) is reasonable
   - We want PID to react to recent training state, not synthetic eval metric

3. **Impact on PID behavior:**
   - Coherence gate now functional
   - PID can detect "coherence alarm" states (< 0.3)
   - Authority factor properly modulated by actual model health

### Expected Behavior

| Before | After |
|--------|-------|
| PID coherence always 0.75 | PID coherence reflects actual O1↔O12 similarity |
| Coherence gate always "healthy" | Coherence gate responds to model state |
| LR decisions ignore cognitive state | LR decisions informed by coherence |

## Fix 2: T-Axis Sign Inversion (HIGH)

### The Problem

The Kosha steering system was targeting the wrong quadrant because the T-axis (Time) computation had an inverted sign.

**Quadrant Geometry (from KOSHA_GYROSCOPE_DESIGN.md):**
```
                       TIME AXIS
                    + (PAST)
                        │
     MENTAL (-,+)       │       PHYSICAL (+,+)
                        │
- (UNMANIFEST) ─────────┼───────── + (MANIFEST)  REALITY AXIS
                        │
     BLISSFUL (-,-)     │       INTELLECT (+,-)
                        │
                    - (FUTURE)
```

### Root Cause Analysis

**Documentation states:**
- T-Axis (Time): Past (+) ↔ Future (-)
- **Low gradient** = Static, repeating, stuck in patterns = **Past (+T)**
- **High gradient** = Dynamic, projecting, novel trajectory = **Future (-T)**

**Original code at `train_unified_llm.py:11801`:**
```python
# BEFORE: Wrong sign
t_axis = math.log(t_axis_grad + 1e-8) / 2.3
```

This produced:
- High gradient (10.0) → log(10) ≈ 2.3 → t_axis ≈ +1.0 (Past) ❌
- Low gradient (0.1) → log(0.1) ≈ -2.3 → t_axis ≈ -1.0 (Future) ❌

**The mapping was inverted!**

### The Fix

**Location:** `train_unified_llm.py:11805`

```python
# V9.8.5: SIGN FIX - Documentation states:
#   High gradient → Future (-T) = Dynamic, projecting
#   Low gradient  → Past (+T)   = Static, repeating
# Original code had this inverted. Negating to match doc.
t_axis = -math.log(t_axis_grad + 1e-8) / 2.3  # Negated!
```

### Reasoning

1. **Physical interpretation:**
   - High gradient norm = large weight updates = model actively learning/changing
   - Low gradient norm = small updates = model stable/converged

2. **Quadrant mapping (corrected):**
   | R-axis (Entropy) | T-axis (Gradient) | Target Quadrant |
   |------------------|-------------------|-----------------|
   | +R (low entropy, certain) | -T (high grad, dynamic) | **Intellect** |
   | +R (low entropy, certain) | +T (low grad, static) | **Physical** |
   | -R (high entropy, uncertain) | -T (high grad, dynamic) | **Bliss** |
   | -R (high entropy, uncertain) | +T (low grad, static) | **Mental** |

3. **Example scenario:**
   - Model is grounded (low entropy → +R) and actively reasoning (high gradient → -T)
   - Should target **Intellect quadrant** (+R, -T)
   - Before fix: Was targeting **Physical quadrant** (+R, +T) - wrong!

### Expected Behavior

| Scenario | Before (Wrong) | After (Correct) |
|----------|---------------|-----------------|
| Grounded + Dynamic | Physical (+R,+T) | Intellect (+R,-T) |
| Grounded + Static | Intellect (+R,-T) | Physical (+R,+T) |
| Uncertain + Dynamic | Mental (-R,+T) | Bliss (-R,-T) |
| Uncertain + Static | Bliss (-R,-T) | Mental (-R,+T) |

## Fix 3: Vital-Coherence Coupling (MEDIUM)

### The Problem

Pranamaya (Vital) kosha was a purely learned representation with no grounding in physical signals. The user's insight:

> "Vital is the living medium whose sole purpose is to be consumed as coherence is achieved between the other four koshas."

But Vital had no connection to coherence - the model could report high Vital while having low coherence (or vice versa).

**Four Conscious Koshas + One Living Medium:**

```

│                    CONSCIOUS KOSHAS                              │
│                                                                  │
│   Physical ─────────────────────────────── Intellect            │
│   (Annamaya)        ↑         ↑            (Vijnanamaya)        │
│                     │         │                                  │
│              ┌──────┴─────────┴──────┐                          │
│              │                       │                          │
│              │   VITAL (Pranamaya)   │  ← LIVING MEDIUM         │
│              │                       │    Depletes as coherence │
│              │   The energy that     │    is achieved           │
│              │   animates transitions│                          │
│              │                       │                          │
│              └──────┬─────────┬──────┘                          │
│                     │         │                                  │
│   Mental ───────────┘         └─────────────── Bliss            │
│   (Manomaya)                               (Anandamaya)         │
└─────────────────────────────────────────────────────────────────┘
```

### The Implementation

**Location:** `symbolu/losses/kosha_gyroscope.py:889-915`

```python
# v9.8.5: Coherence-Vital Coupling (Conservative)
#
# Why Toroidal Coherence is the correct metric:
# - Vital controls MOMENTUM (maintains direction/trajectory)
# - Toroidal coherence measures trajectory consistency (O1↔O12)
# - High coherence = stable trajectory = less momentum needed
# - Suppressing momentum boost when coherent is physically correct
#
# Conservative scaling (20% max reduction):
# - Avoids "Fake Flow" crash scenario
if coherence is not None:
    coh_factor = max(0.0, min(1.0, (coherence - 0.3) / 0.4))
    # Floor morphs from 23.6% to ~18.9% - 20% max reduction
    effective_vital_floor = self.floor_vital * (1.0 - 0.20 * coh_factor)
else:
    effective_vital_floor = self.floor_vital
```

### Reasoning

1. **Why Toroidal Coherence is correct for Vital:**
   - Vital controls **momentum** (maintains trajectory direction)
   - Toroidal coherence measures **trajectory consistency** (O1↔O12)
   - If trajectory is consistent (high coherence), you don't need momentum
   - Suppressing momentum boost when coherent is physically correct

2. **Why we ALLOW depletion rather than FORCE it:**
   - The implementation lowers the **floor** (minimum acceptable Vital)
   - When coherent, model doesn't get momentum boost even at lower Vital
   - This allows natural depletion without forcing it
   - The four conscious koshas still drive the actual Vital value

3. **Why 20% is conservative (not 36%):**
   - **Fake Flow scenario:** Model has high coherence but wrong direction
   - At 36% reduction (floor = 15%), model starves itself of momentum
   - At 20% reduction (floor = 18.9%), safety buffer remains
   - Can increase to 36% after observing stable behavior

4. **The coherence bands (0.3 - 0.7):**
   - 0.3 = Existing "coherence alarm" threshold (struggling)
   - 0.7 = Existing "good coherence" threshold in PID
   - Linear interpolation provides smooth transition

### Vital Floor Modulation Table

| Coherence | coh_factor | Vital Floor | Momentum Boost |
|-----------|------------|-------------|----------------|
| ≤ 0.3 (struggling) | 0.0 | 23.6% | Triggers at Vital < 23.6% |
| 0.5 (neutral) | 0.5 | 21.2% | Triggers at Vital < 21.2% |
| ≥ 0.7 (flow state) | 1.0 | **18.9%** | Triggers at Vital < 18.9% |

### Expected Behavior

| Scenario | Vital | Coherence | Before | After |
|----------|-------|-----------|--------|-------|
| Flow state | 20% | 0.8 | Boost (20% < 23.6%) | No boost (20% > 18.9%) |
| Struggling | 20% | 0.2 | Boost | Boost (20% < 23.6%) |
| Efficient depletion | 15% | 0.8 | Boost | Boost (15% < 18.9%) |
| Energy crisis | 15% | 0.2 | Boost | Boost (15% < 23.6%) |
