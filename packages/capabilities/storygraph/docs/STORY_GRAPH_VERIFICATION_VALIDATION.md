# StoryGraph Verification & Proof-Semantics Validation — Run 3

A narrow verification phase. **No new domains, StoryGraphs, PageRank, ML,
probabilistic scoring, unknown-pattern discovery, trading applications, or detection
features.** It answers four questions: was the final split genuinely independent;
are witnesses truly minimal under duplicates; do all mandatory-edge states fail
closed; and is missing legitimate context ever treated as harmful evidence.

Prior evidence preserved: `evaluation/prior_runs.py` (`RUN_1`, `RUN_2`, `RUN_3`),
`STORY_GRAPH_EVIDENCE_LEDGER.md`, `STORY_GRAPH_FINAL_SPLIT_AUDIT.md`. Commits
`78934f…`/`019e1f0d` and all Run-1/Run-2 hashes, metrics, and verdicts are intact.

## 1. Final-split independence (§3, §4) — Outcome B: exposed → replaced

**Finding: the Run-2 final split was NOT independent.** `evaluate_corpus()` was run
over the full 108-case corpus (all splits) before freeze; the corpus/coverage model
was then tuned after observing those aggregates, and 8 of 31 Run-2 final cases had
their modeling changed afterward. Full audit: `STORY_GRAPH_FINAL_SPLIT_AUDIT.md`.

**Disposition:** the Run-2 final split is retained as development evidence; a
**replacement held-out final split** is generated by a frozen generator
(`ctd.storycorpus.gen/2.0.0`) under a new seed (`[911,912,913]`), with no manual
selection. It is disjoint from the development corpus
(`final_eval.dev_corpus_excludes_holdout() is True`), and **no development or
calibration command evaluates it** — only the guarded `final_eval.run_official_final`
does, after `freeze.require_frozen(official=True)`. Its case-id hash is frozen
*without* evaluating outcomes.

## 2. Evaluation-access controls (§5)

`evaluation/final_eval.py` `run_official_final(...)`:
requires the frozen config; **refuses development mode**; refuses a modified graph /
provider / policy / corpus / matcher / generator (freeze drift); emits **one
immutable evaluation record** (with `record_digest`, `commit`, `invoked_at`); and
**refuses a second official run** unless `allow_new_generation=True` (which bumps a
`generation` counter). The development/calibration commands operate on the exposed
corpus only and cannot reach the holdout by construction.

## 3. Witness canonicalization under duplicates (§6-§8)

Tie-break versioned `ctd.witness.tiebreak/2.0.0`. Semantically-equivalent events
(same fragment + actor + account/device/beneficiary/destination/amount; transport
record-ids ignored) collapse to **one canonical representative per node**.
`CompletionWitness` now returns `canonical_witness`, `excluded_equivalent_events`,
`equivalence_classes`, plus `minimality_verified` and class-level `removal_proofs`.
Minimality is proven by removing each representative's **entire equivalence class**
and confirming completion breaks — so a witness is strictly minimal even under
duplicate/retry storms, while duplicate provenance stays visible. Materially
distinct events (conflicting payloads, genuinely distinct candidates) are **never**
collapsed; a real multiplicity is reported (`multiple_optimal_bindings ≥ 2`), not
silently minimized. Tests: `tests/test_witness_and_mandatory.py` (12 witness cases
incl. single/multiple duplicate resets, duplicate devices/beneficiaries, retries
with different record ids, conflicting payloads, genuinely-distinct eligibles,
duplicate-proposed already-complete, digest stability).

## 4. Mandatory-edge fail-closed completion (§9, §10)

Exact completion requires **every required node present and every mandatory edge
positively `SATISFIED`**. `StoryMatch.completion_blockers()` makes the rule explicit;
`is_complete()` derives from it. Proven directly: mandatory `FAILED` → not complete;
mandatory `NOT_EVALUABLE` → not complete; mandatory `AMBIGUOUS` → not complete;
mandatory `SATISFIED` (all) → complete; optional `NOT_EVALUABLE` → does not block; no
weighted value compensates an unsatisfied mandatory edge. Partial-risk observation is
kept separate from completion proof and never treats missing/non-evaluable evidence
as positive proof.

## 5. Imperfect-but-benign context (§11, §12)

New context-status axis (separate from the harmful category):
`VERIFIED_LEGITIMATE`, `PARTIALLY_VERIFIED_LEGITIMATE`, `LEGITIMATE_CONTEXT_UNAVAILABLE`,
`LEGITIMATE_CONTEXT_CONFLICTING`, `LEGITIMATE_CONTEXT_STALE`,
`LEGITIMATE_CONTEXT_NOT_FOUND`, `HARMFUL_STRUCTURE_POSITIVELY_SUPPORTED`. A partial
material story that cannot be neutralized only because context is unavailable/stale/
conflicting yields `ADDITIONAL_CONTEXT_REQUIRED` (OBSERVE) — not a stronger harmful
assertion. **The harmful structural vector is byte-identical with and without the
context signals** (`incorrect_harmful_strengthening_from_missing_context = 0`), and no
context-gap case is falsely neutralized as VERIFIED
(`incorrect_benign_neutralization = 0`). 14 imperfect-benign families added.

## 9. Known limitations

Single synthetic domain; hand-built corpus; equivalence uses a fixed material-field
key (not per-node edge-relevant fields), so it is conservative — it never
over-collapses, but two events distinct only in a field irrelevant to a given node
are treated as a real multiplicity rather than duplicates; several operational
metrics require enterprise data and are NOT RUN.
